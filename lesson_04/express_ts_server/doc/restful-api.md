# RESTful API
RESTful API -архитектурный стиль взаимодействия между приложенями
Он основан на протоколе HTTP. Т.е. описание правил обмена данными между клинтом и сервером.

1. Resurses
-URL - Uniform Resource Locator (путь по которому можно найти необходимый ресурс)

Используются существительные (в ед. или мн. числе)
НЕ использовать глаголы!!!

/users - получить данные всех пользователей
/users/629 - получить данные пользователя по ID или
                для удаления пользователя с id (629) в зависимости от метода

ПРИМЕРЫ ПЛОХИХ НАЗВАНИЙ:
/getAllUsers
/users/18/posts/14 (излишняя вложенность - это плохо)

САМЫЙ ЛУЧШИЙ СПОСОБ
/user-profile (kebab case)

Переменные пути
/users/:id

Quеry params (параметры запроса)
url?key=value&key=value (/products?size=32&color=red)

2. Клиент - сервер
METHODS
CRUD

CREATE - POST (/users)
READ - GET - получить всех пользователей (/users)
UPDATE - PUT- отредактировать данные (/user:id)
        PATCH - частичное редактирование данных (/user:id)
DELETE - DELETE - удалить пользователя (/users)

STATUS CODE

100 - 109 - info
200 - 299 - success (201 - created)
300 - 399 - redirect
400 - 499 - client err0r
500 - 599 - server error

3. Stateless - отсутствие состояния. Сервер не хранит данные о запросах, которые были отправлены. Каждый запрос должен иметь необходимую информацию.

4. Единообразие.
Вся информация которую мы передаем должна быть в одном формате - JSON
